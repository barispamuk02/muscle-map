## Распределение 78 отметок

| Правило | Количество | Следующее действие |
|---|---:|---|
| `STRETCH_ROLE_REVIEW` | 56 | Различить растягиваемую мышцу и сокращающегося двигательного участника |
| `REAR_DELTOID_ROLE_CHECK` | 12 | Проверить по движениям задней дельты, часть названий включает тяги, где целевая мышца может отличаться |
| `DUPLICATE_ENGLISH_NAME` | 6 | Сохранить разные ID; проверить, действительно ли разные варианты имеют одинаковую английскую подпись |
| `MISSING_ATLAS_TARGET` | 2 | Источник помечает `levator scapulae`, отдельная мышца пока отсутствует в атласе |
| `RECTUS_FEMORIS_CONFUSION` | 1 | Разобрать упражнение ID `1714`: `assisted prone rectus femoris stretch`, которое ошибочно может относиться к прямой мышце живота вместо прямой мышцы бедра |
| `UNVERIFIED_PERCENTAGES` | 1 | Не публиковать шаблонные проценты синергистов как измеренный вклад мышц |

Проверка задней дельты выявила 12 **кандидатов** для анализа. Нельзя автоматически переносить все упражнения, названия которых содержат `rear delt`, в заднюю дельту, так как техника, роль мышц и источник упражнения могут различаться. Примеры: ID `0075` (`barbell rear delt raise`), `1022` (`band standing rear delt row`), `1328` (`dumbbell lying rear delt row`). Упражнение `rear deltoid stretch` также должно учитываться как растяжка, а не упражнение с теми же активными мышцами.

## Автоматические инструменты

- `scripts/audit-exercises.cjs`: автономная проверка данных без внешних запросов и изменения рабочих баз.
- `tests/exercise-audit.test.cjs`: тест полноты, отсутствия структурных ошибок и запрета неподтверждённой экспертной маркировки.
- `.github/workflows/exercise-data-audit.yml`: выполнение на Pull Request и публикация артефактов.
- `reports/exercises-audit.json`: полный машиночитаемый список результатов CI, включая каждый идентификатор.
- `reports/exercises-audit.md`: обзор со ссылками по идентификаторам и группировкой проблем.
- `reports/exercises-review-index.csv`: **1295 строк для проверки** по стабильному exercise ID с пустыми полями источников, проверяющего и даты; исходный статус `unreviewed`.

Файлы `reports/*` производятся при запуске CI и загружаются как артефакты GitHub Actions; **они не записываются автоматически в Production или репозиторий**.

Локальный запуск при наличии Node.js из корня репозитория:

```powershell
node scripts/audit-exercises.cjs --json reports/exercises-audit.json --markdown reports/exercises-audit.md --review-csv reports/exercises-review-index.csv --fail-on-errors
node --test tests/exercise-audit.test.cjs
```
